## Objective & done criteria

`example-upload` began as a **BFFless demo site** (Home / Forms / Comments / Chat / Auth) and grew a
full app — **Studio** — that no longer belongs in a demo. Studio should ship for free as part of
BFFless's distribution strategy: BFFless is the platform, Studio is one app for it, more apps follow.

**Done when:** Studio lives in a new pnpm monorepo (`bffless-apps`) as a self-contained app that
builds/lints/tests green and deploys via its own GitHub Action; this repo is the demo site only,
with the monorepo attached as a git submodule; both repos are green end-to-end.

<Callout kind="decision" title="The load-bearing choices (locked with James)">
**1.** Demo site **stays standalone** in this repo — only Studio moves. &nbsp;
**2.** Apps are **self-contained for now** — no shared `packages/*` yet; Studio copies the few shared
bits it uses, extract packages later. &nbsp;
**3.** **Clean-start** git history — copy Studio in as the monorepo's first commit. &nbsp;
**4.** **Per-app, path-filtered** deploy workflows — clone the monorepo, deploy any one app.
</Callout>

<Callout kind="warn" title="Risk: the @ffmpeg/core-mt patch under pnpm">
`scripts/patch-core-mt.mjs` edits files **inside `node_modules/@ffmpeg/core-mt`** on `postinstall`
(it raises the MT heap 1→3 GiB and fixes the module-worker). pnpm breaks two assumptions:
(1) it **skips a project's pre/post scripts by default** → add `enable-pre-post-scripts=true` to
`.npmrc`; (2) its `node_modules` is a **symlinked content-addressed store** → editing the link
mutates the shared copy. **Prefer** converting to `pnpm patch` / `pnpm.patchedDependencies`
(deterministic, store-safe). **Must verify** a real assemble runs (MT core loads, 3 GiB heap) under
pnpm — this is the only path that could silently regress.
</Callout>
